# The post-PR Notification is one-way, never a wait-for-approval Gate

The intent going in was a real chat-platform approval step — send a message and block until someone approves it. But most chat/messaging MCP tools (Slack, Cliq, Teams, etc.) can only send messages and list chats/channels — none can reliably read a reply in a generic way. Building a wait-for-reply gate on top of that would mean polling blind or guessing from a channel listing, which is worse than no gate at all. So the Notification is explicitly FYI-only: sent after the PR opens, carrying no approval semantics. The real Approval Gates all stay in-chat, in this conversation. If a true platform-approval gate is wanted later, it needs a message-reading capability first — this decision should be revisited then, not worked around.
